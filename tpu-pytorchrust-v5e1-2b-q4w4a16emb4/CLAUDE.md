# CLAUDE.md — tpu-pytorchrust-v5e1-2b-q4w4a16emb4

Gemma 4 E2B on a TPU v5e-1 with the model in Rust (`rust/`, a PyO3 extension over its own ATen shim) and every op a TorchTPU kernel. One Claude Code skill (`tpu-pytorchrust-v5e1-2b-q4w4a16emb4-management`) and one MCP server (`server.py`) provision and operate it. Sister rig: `../tpu-pytorch-v5e1-2b-w4a16` (same chip, Python model). The engine came from `../colab/rust/`; forks are copies, so a fix in one does not reach the other.

## Sources and generated copies

- **Sources:** `server.py`, `rust_openai_server.py`, `rust/`, `project-setup.sh`, `requirements.txt`, `tpu.env`, `tpu.md` (private, gitignored).
- **Hand-maintained in the skill:** `SKILL.md`, `mcp/startup_script_rust_template.sh` (rendered with `str.format`: double every literal brace).
- **Generated by `make skill`:** the skill's `mcp/{server.py,project-setup.sh,requirements.txt}`, `mcp/payload/` (the crate sources and `rust_openai_server.py`, which `server.py` packs into the startup script), `references/tpu-guide.md`, and the plugin copy under `skills/`. Never edit them directly; `tests/test_server.py` fails when they drift.
- `server.py` `_PAYLOAD_FILES` and `refresh_skill.py` `PAYLOAD_FILES` list the same files. Add a crate file to both.

## The PyO3 rules that shape the code

- Every PyO3 item is in `rust/src/bindings.rs`. `gemma.rs` and `weights.rs` stay free of Python types. Keep `rust/PYO3.md` and `rust/python/torchtpu_rs.pyi` in step with `bindings.rs`.
- `Engine` is `#[pyclass(unsendable)]`. Only the thread that built it may call it; `rust_openai_server.py` gives it one worker thread and a queue. Another thread gets `PanicException` (a BaseException).
- Long calls run inside `py.detach`, and the `on_tokens` callback re-attaches with `Python::attach`. A closure inside `detach` must be `Send`: move a `Tensor` into it, never borrow one (`Tensor` is not `Sync`).
- Import order at run time: `torch`, then `torch_tpu`, then `torchtpu_rs`.
- No `tch`. `rust/src/aten.cpp` wraps the ATen ops the model uses; `build.rs` compiles it (C++20) against the torch that `PYO3_PYTHON` (else `python3`) imports, so no PyTorch version is pinned. A new op means a wrapper in `aten.cpp`, its declaration and method in `aten.rs`. The module raises ImportError if the running torch differs from the one it was built against.
- Toolchain: `rust/rust-toolchain.toml` (newest nightly), edition 2024. The VM installs that channel; `server.py` reads it from the file.

## Provisioning facts

- v5e-1 is a queued resource (`gcloud alpha compute tpus queued-resources create`, runtime `v2-alpha-tpuv5-lite`); `gcloud compute instances create` rejects `ct5lp-*`.
- A TPU VM has no serial-port command. The startup script writes its stage to the guest attribute `torchtpu-rs/stage`; `get_rig_progress` reads it with `get-guest-attributes`. The queued resource is created with `enable-guest-attributes=TRUE` and the `SERVE_TAGS` network tags.
- No virtualenvs, locally or on the VM: the VM installs into a dedicated `PYTHON_BIN` (python3.14, deadsnakes) with `--break-system-packages`.
